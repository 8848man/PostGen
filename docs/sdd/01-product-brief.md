# Product Brief

> 이 문서는 기존 Codex Skill MVP의 기준선이다. 다중 입력·계정별 골든 샘플·예약 편집기 준비로 확장하는 승인된 제품 방향의 단일 원본은 [Next Product Brief](next/01-product-brief.md)다. 기존 MVP의 구현 상태와 새 제품의 목표 상태를 혼동하지 않는다.

## 문제와 목표

AI 협업 기록의 사실, 결정, 예시와 해석을 사람이 이해하기 쉬운 콘텐츠로 전환한다. 첫 매체는 블로그다. 핵심 가설은 “별도 설정 없이 AI 작업 기록에서 최소 수정으로 게시 가능한 블로그 초안을 얻을 수 있다”이다.

**제품 목표:** Postgen은 특정 AI 실행 호스트에 종속되지 않아야 한다. Codex에서 먼저 검증하되 Claude Code, Claude Cowork와 이후 호환 가능한 AI 호스트에서도 같은 콘텐츠 계약과 사용자 경험으로 사용할 수 있어야 한다. 각 호스트의 Skill 설치·호출·파일 접근·모델 기능은 Adapter로 분리한다. 이 목표는 입력으로 Claude 기록을 읽는 기능과 별개다.

## 확정 제품 형태

- MVP의 기본 진입점은 **Codex CLI의 콘텐츠 제작 Skill**이다. 별도 웹 앱에서 글을 생성하지 않는다.
- Skill이 현재 작업 폴더와 연결된 Codex·Claude Code 기록을 자동 탐색한다. 실행 호스트는 Codex다. 사용자는 기본 흐름에서 기록과 주제를 선택하지 않는다.
- `생성 전에 주제 선택하기`는 기본 꺼짐이며, 켜면 생성 전에 주제 후보를 선택한다.
- 로컬 인터랙티브 HTML 설정 화면은 MVP 필수다. 프리셋, Style Profile, 레퍼런스, 설정 채팅을 다루되 기본 제작의 필수 단계는 아니다.
- Codex만 현재 MVP의 **구현·검증된 실행 호스트**다. Claude Code·Cowork 및 다른 호스트에서의 실행은 필수 후속 목표이며 현재 구현 완료로 표시하지 않는다.
- 초안은 CLI 대화에 먼저 보이며, 명시적 내보내기 요청 때 Markdown/HTML 파일을 저장한다.
- 후속 제품 흐름은 사용자가 요청한 초안을 채널별로 변환해 브라우저 편집기에 준비하고, 확인 후 X·Threads·네이버 블로그·티스토리에 등록하는 것이다(ADR-012). 기본 글 생성에는 발행 단계를 끼워 넣지 않는다.

## 제품 원칙

1. Zero Configuration: Skill 호출만으로 기본 프로필에서 시작한다.
2. ELI5: 전문 용어에는 문맥에 맞는 쉬운 설명과 예시를 제공한다.
3. Evidence-Based Generation: 원문 사실, 사용자 결정, AI 해석을 구분하고 근거 위치를 추적한다.
4. Progressive Disclosure: 프리셋과 고급 설정은 요청 또는 적절한 제안 때 연다.
5. Style Consistency: 수락된 지속 선호만 후속 글에 적용한다.
6. Medium Independence: 기록 해석 결과와 블로그 표현 규칙을 분리한다.

## 성공 지표와 측정

- 핵심 지표: 첫 초안 중 사용자가 게시 가능하다고 판단한 비율, 게시 전 의미 있는 수정 횟수, 첫 초안까지 걸린 시간.
- 신뢰 지표: 근거 없는 사실 주장 비율, 사실 오류 수정 횟수, 의도하지 않은 다른 프로젝트 정보 혼입 건수.
- UX 지표: 첫 글에 설정/선택 단계가 강제된 건수(목표 0), 스타일 제안 수락·거절 후 반복 노출 건수.
- 초기 목표 수치는 파일럿 데이터가 없으므로 정하지 않는다. 테스트 전략에서 기준선을 수집한다.
