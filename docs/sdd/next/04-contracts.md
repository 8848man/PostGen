# Data Contracts

모든 지속 객체는 `schemaVersion`, 안정적 ID, `revision`, 생성·수정 시각을 가진다. 시간은 ISO 8601 UTC로 저장하고 화면에서 사용자 시간대로 표시한다. 버전 변경은 명시적 마이그레이션을 요구한다. 실제 필드 이름과 검증 구현은 각 단계에서 이 문서에 맞춰 확정한다.

| 객체 | 필수 의미 |
| --- | --- |
| `AccountProfile/v1` | 채널, 계정 식별자, 기본 목표, 대표 샘플 ID, 자산 ID 목록. 인증 비밀은 포함하지 않음 |
| `GoldenSample/v1` | 계정 ID, 입력 유형·위치, 사용 권한 선언, 승인 상태, 필수·선호 규칙, 원본/추출 규칙 버전 |
| `VisualAsset/v1` | 계정 ID, 종류(캐릭터/오브젝트 등), 자산 위치, 외형 유지 특징, 사용 권한 선언 |
| `SourceBundle/v1` | 사용자가 선택한 출처 ID 목록, 원본 사본, 출처 유형·위치·수집 시각, 읽기 오류 |
| `EvidencePlan/v1` | 핵심 주장, 출처 참조, 충돌, 계정 공통 기획. 로컬 경로·세션 ID를 게시 페이로드에 넣지 않음 |
| `AccountDraft/v1` | 계정 ID, 독자, 목표, 샘플/규칙 버전, 본문·이미지 제안, 주장별 근거, 자동 점검·사용자 평가 |
| `PublicationPreparation/v1` | 계정별 승인본 ID, 예약 시각, 만료 시각, 상태, 편집기 읽기 결과, 업로드 검증, 최종본 차이, 게시 URL |

## 상태와 불변식

- 샘플 규칙은 `proposed → approved`로 전환한다. 미승인 규칙은 기본값으로 사용하지 않는다. `required`와 `preferred`를 구별한다.
- 초안은 계정별 개별 revision을 갖는다. 승인 시점의 내용·이미지·샘플 규칙 버전을 스냅샷으로 고정한다. 수정하면 재승인한다.
- `AccountDraft`의 편집 잠금은 작업 ID별로 두며, 소유자 토큰·만료 시각을 로컬 잠금 파일에 보관한다. 화면은 수정 입력 전에 잠금을 얻고 저장·취소 후 해제한다. 잠금 유효 기간은 30분이며 만료 뒤 다른 작성자가 획득할 수 있다. 저장은 유효한 토큰과 읽을 때의 초안 revision을 요구한다. 토큰이 없거나 만료됐거나 revision이 달라지면 쓰기를 거절하고 새로고침을 안내한다. Skill CLI의 쓰기도 동일한 잠금 검사를 통과해야 한다. 잠금 파일은 게시 페이로드에 포함하지 않는다.
- `jobs.json`의 모든 저장은 파일 단위 배타 잠금 안에서 현재 전체 revision을 재확인한 뒤 임시 파일을 교체한다. 편집 잠금의 획득·해제 역시 이 잠금 안에서 처리해 저장과 경합하지 않게 한다. 비정상 종료로 남은 파일 잠금은 만료 후 복구한다. 잠금 실패는 자동 덮어쓰기나 무한 재시도가 아니라 명시적 오류다.
- 새 플랫폼 예약 작업은 `approved → awaiting_registration → preparing → ready_to_register → submitting → registered → verification_due → published`로 진행한다. 편집 내용이 승인본과 다르면 `review_required`, 등록 결과가 불명확하면 `unknown`으로 둔다. `unknown`은 자동 재제출하지 않는다. 이전 로컬 예약 데이터의 `scheduled`·`due`는 읽을 수 있지만 새 작업은 만들지 않는다. `published`는 화면 증거 또는 사용자가 입력한 게시 URL의 출처를 기록한다.
- MCP 서버 등록 시 제공 도구와 권한 범위를 사용자에게 보여주고 서버 단위로 허용한다. 제공 기능이 바뀌면 새 기능을 자동 허용하지 않으며 재검토한다. 즉시 게시 기능은 첫 출시 자동 호출 대상이 아니다.
- 연결 비밀은 콘텐츠 JSON, 로그, 모델 프롬프트에 넣지 않는다. 데이터는 로컬에 저장한다. 모델·MCP로 보내는 자료의 범위와 비용을 실행 전에 표시한다.
- 이미지 생성 비용은 `POSTGEN_PRICE_TABLE`의 `image:openai:<model>:generation|edit` 항목에 양수 `perImageUsd`, `verified: true`, `sourceUrl`, `verifiedAt`이 있을 때만 계산한다. 최대 생성 횟수를 곱해 상한 성격의 생성비 추정치를 보여준다. 가격표가 없거나 항목이 불완전하면 금액은 `추정 불가`다. 자동 이미지 점검은 별도 모델 요청이고 실제 토큰·이미지 입력량을 사전에 알 수 없으므로 총액에 포함하지 못한 비용을 명시한다. 추정치와 가격표는 실제 청구액을 보증하지 않으며, 알 수 없는 비용 또는 설정 한도 초과는 실행 전 확인을 요구한다.
- 원본·중간 결과의 보관 기간은 1~3개월이고 기본 3개월이다. 앱 실행 시 및 실행 중 하루 1회 모든 작업의 만료 원본 사본·공통 근거 기획·진단 기록을 활성 작업에서 제거한다. 제거 자료는 작업 ID와 제거·영구 삭제 시각을 기록해 14일 동안 복원할 수 있고, 이후 영구 삭제한다. 복원한 자료는 14일간 재정리하지 않는다. 초안 본문·이미지·URL·평가 및 계정 샘플·자산은 유지한다. 앱이 실행되지 않는 동안 정리는 진행되지 않는다.

## 현재 구현과 남은 검증

`account-registry/v1`은 계정·샘플·자산의 메타데이터, 승인, 대표 샘플을 저장한다. `postgen-next/v1` 작업은 선택 출처 사본, 계정별 초안과 상태 전이를 저장하고 Skill CLI와 로컬 화면이 함께 사용한다. 초안별 편집 잠금과 저장 직렬화, 14일 복원 보관·영구 삭제는 합성 테스트를 통과했으나 장시간·실사용 경합과 실제 데이터 복원은 미검증이다. 샘플 URL/캡처 분석, 이미지 바이트 수집·생성, 자동 점검 경로는 구현했으나 실계정·실 API에서 아직 검증하지 않았다. 승인 당시 샘플 규칙의 불변 스냅샷과 게시 URL 자동 확인도 남아 있다. 구현 상태는 [단계별 범위](02-delivery-scope.md)를 따른다.
