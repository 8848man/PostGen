# Data Contracts

모든 지속 객체는 `schemaVersion`, 안정적 ID, `revision`, 생성·수정 시각을 가진다. 시간은 ISO 8601 UTC로 저장하고 화면에서 사용자 시간대로 표시한다. 버전 변경은 명시적 마이그레이션을 요구한다. 실제 필드 이름과 검증 구현은 각 단계에서 이 문서에 맞춰 확정한다.

| 객체 | 필수 의미 |
| --- | --- |
| `AccountProfile/v1` | 채널, 계정 식별자, 기본 목표, 대표 샘플 ID, 자산 ID 목록. 인증 비밀은 포함하지 않음 |
| `GoldenSample/v1` | 계정 ID, 입력 유형·위치, 사용 권한 선언, 승인 상태, 필수·선호 규칙, 원본/추출 규칙 버전 |
| `VisualAsset/v1` | 계정 ID, 종류(캐릭터/오브젝트 등), 자산 위치, 외형 유지 특징, 사용 권한 선언 |
| `SourceBundle/v1` | 사용자가 선택한 출처 ID 목록, 원본 사본, 출처 유형·위치·수집 시각, 읽기 오류 |
| `EvidencePlan/v1` | 핵심 주장, 출처 참조, 충돌, 계정 공통 기획. 로컬 경로·세션 ID를 게시 페이로드에 넣지 않음 |
| `AccountDraft/v1` | 계정 ID, 독자, 목표, 샘플/규칙 버전, 본문·이미지 제안, 주장별 근거, 자동 점검·사용자 평가 |
| `PublicationPreparation/v1` | 계정별 승인본 ID, 예약 시각, 만료 시각, 상태, 편집기 읽기 결과, 업로드 검증, 최종본 차이, 게시 URL |

## 상태와 불변식

- 샘플 규칙은 `proposed → approved`로 전환한다. 미승인 규칙은 기본값으로 사용하지 않는다. `required`와 `preferred`를 구별한다.
- 초안은 계정별 개별 revision을 갖는다. 승인 시점의 내용·이미지·샘플 규칙 버전을 스냅샷으로 고정한다. 수정하면 재승인한다.
- 새 플랫폼 예약 작업은 `approved → awaiting_registration → preparing → ready_to_register → submitting → registered → verification_due → published`로 진행한다. 편집 내용이 승인본과 다르면 `review_required`, 등록 결과가 불명확하면 `unknown`으로 둔다. `unknown`은 자동 재제출하지 않는다. 이전 로컬 예약 데이터의 `scheduled`·`due`는 읽을 수 있지만 새 작업은 만들지 않는다. `published`는 화면 증거 또는 사용자가 입력한 게시 URL의 출처를 기록한다.
- MCP 서버 등록 시 제공 도구와 권한 범위를 사용자에게 보여주고 서버 단위로 허용한다. 제공 기능이 바뀌면 새 기능을 자동 허용하지 않으며 재검토한다. 즉시 게시 기능은 첫 출시 자동 호출 대상이 아니다.
- 연결 비밀은 콘텐츠 JSON, 로그, 모델 프롬프트에 넣지 않는다. 데이터는 로컬에 저장한다. 모델·MCP로 보내는 자료의 범위와 비용을 실행 전에 표시한다.
- 원본·중간 결과의 보관 기간은 1~3개월이고 기본 3개월이다. 만료 삭제는 최종 콘텐츠·이미지·URL·평가 및 계정 샘플·자산에 적용하지 않는다.

## 현재 구현과 남은 검증

`account-registry/v1`은 계정·샘플·자산의 메타데이터, 승인, 대표 샘플을 저장한다. `postgen-next/v1` 작업은 선택 출처 사본, 계정별 초안과 상태 전이를 저장하고 Skill CLI와 로컬 화면이 함께 사용한다. 샘플 URL/캡처 분석, 이미지 바이트 수집·생성, 자동 점검 경로는 구현했으나 실계정·실 API에서 아직 검증하지 않았다. 동시 편집 중 읽기 전용 잠금, 승인 당시 샘플 규칙의 불변 스냅샷, 게시 URL 자동 확인도 남아 있다. 구현 상태는 [단계별 범위](02-delivery-scope.md)를 따른다.
