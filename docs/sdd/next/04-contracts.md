# Data Contracts

모든 지속 객체는 `schemaVersion`, 안정적 ID, `revision`, 생성·수정 시각을 가진다. 시간은 ISO 8601 UTC로 저장하고 화면에서 사용자 시간대로 표시한다. 버전 변경은 명시적 마이그레이션을 요구한다. 실제 필드 이름과 검증 구현은 각 단계에서 이 문서에 맞춰 확정한다.

| 객체 | 필수 의미 |
| --- | --- |
| `AccountProfile/v1` | 채널, 계정 식별자, 기본 목표, 대표 샘플 ID, 자산 ID 목록. 인증 비밀은 포함하지 않음 |
| `GoldenSample/v1` | 계정 ID, 입력 유형·위치, 사용 권한 선언, 승인 상태, 필수·선호 규칙, 원본/추출 규칙 버전 |
| `VisualAsset/v1` | 계정 ID, 종류(캐릭터/오브젝트 등), 자산 위치, 외형 유지 특징, 사용 권한 선언 |
| `SourceBundle/v1` | 사용자가 선택한 출처 ID 목록, 원본 사본, 출처 유형·위치·수집 시각, 읽기 오류 |
| `EvidencePlan/v1` | 핵심 주장, 출처 참조, 충돌, 계정 공통 기획. 로컬 경로·세션 ID를 게시 페이로드에 넣지 않음 |
| `AccountDraft/v1` | 계정 ID, 독자, 목표, 샘플/규칙 버전, 본문·이미지 제안, 주장별 근거, 자동 점검·사용자 평가 |
| `AccountDraft/v1` 제목·태그 확장 | 프로젝트 표시명은 작업에 저장한다. 초안 제목은 확인된 프로젝트의 `[프로젝트명] ` 접두어를 한 번만 포함한다. 태그는 중복 없는 문자열 최대 5개이며 기존 초안의 미설정 태그는 빈 목록으로 읽는다 |
| `PublicationPreparation/v1` | 계정별 승인본 ID, 예약 시각, 만료 시각, 상태, 편집기 읽기 결과, 업로드 검증, 최종본 차이, 게시 URL |

## 상태와 불변식

- 샘플 규칙은 `proposed → approved`로 전환한다. 미승인 규칙은 기본값으로 사용하지 않는다. `required`와 `preferred`를 구별한다.
- 초안은 계정별 개별 revision을 갖는다. 승인 시점의 내용·이미지·샘플 규칙 버전을 스냅샷으로 고정한다. 수정하면 재승인한다.
- `draft.standard`의 세트와 지침 SHA-256이 없으면 화면은 `지침 적용 확인 필요`로 표시한다. 일반 검토·승인 API는 이 초안을 거절한다. `발행`을 누르면 `표준 확인이 안된 글입니다. 발행하시겠습니까?` 확인 다이얼로그를 띄우고, 사용자가 발행을 선택한 경우에만 `standardUnverifiedAcknowledged: true`로 예약 발행 API를 호출한다. 서버는 이 명시 확인이 없으면 거절하고, 있으면 승인 기록에 남긴 뒤 기존 이미지·시각·출처 검사를 거쳐 예약 흐름을 이어 간다. 화면 편집은 기존 지침 기록을 보존하고 클라이언트가 보낸 지침 기록으로 바꾸지 않는다.
- `AccountDraft`의 편집 잠금은 작업 ID별로 두며, 소유자 토큰·만료 시각을 로컬 잠금 파일에 보관한다. 화면은 수정 입력 전에 잠금을 얻고 저장·취소 후 해제한다. 잠금 유효 기간은 30분이며 만료 뒤 다른 작성자가 획득할 수 있다. 저장은 유효한 토큰과 읽을 때의 초안 revision을 요구한다. 토큰이 없거나 만료됐거나 revision이 달라지면 쓰기를 거절하고 새로고침을 안내한다. Skill CLI의 쓰기도 동일한 잠금 검사를 통과해야 한다. 잠금 파일은 게시 페이로드에 포함하지 않는다.
- `jobs.json`의 모든 저장은 파일 단위 배타 잠금 안에서 현재 전체 revision을 재확인한 뒤 임시 파일을 교체한다. 편집 잠금의 획득·해제 역시 이 잠금 안에서 처리해 저장과 경합하지 않게 한다. 비정상 종료로 남은 파일 잠금은 만료 후 복구한다. 잠금 실패는 자동 덮어쓰기나 무한 재시도가 아니라 명시적 오류다.
- 새 플랫폼 예약 작업은 `approved → awaiting_registration → preparing → ready_to_register → submitting → registered → verification_due → published`로 진행한다. 편집 내용이 승인본과 다르면 `review_required`, 등록 결과가 불명확하면 `unknown`으로 둔다. `unknown`은 자동 재제출하지 않는다. 이전 로컬 예약 데이터의 `scheduled`·`due`는 읽을 수 있지만 새 작업은 만들지 않는다. `published`는 화면 증거 또는 사용자가 입력한 게시 URL의 출처를 기록한다.
- `cancelled`·`failed` 작업의 재시도는 초안으로 되돌리며 기존 승인·예약·편집기·제출 결과를 지운다. 수동 발행 체크는 `publication.source=manual`, 체크 시각, 이전 상태를 기록한다. 이때 `postUrl`은 없어도 되며 사용자 자기 신고로 표시한다. 체크 해제는 이전 상태로 복원한다. 이미 플랫폼 제출이 시작됐거나 예약 영수증이 있는 작업에는 수동 체크를 허용하지 않는다. 이 경로는 새 플랫폼 제출을 수행하지 않는다.
- MCP 서버 등록 시 제공 도구와 권한 범위를 사용자에게 보여주고 서버 단위로 허용한다. 제공 기능이 바뀌면 새 기능을 자동 허용하지 않으며 재검토한다. 즉시 게시 기능은 첫 출시 자동 호출 대상이 아니다.
- 연결 비밀은 콘텐츠 JSON, 로그, 모델 프롬프트에 넣지 않는다. 데이터는 로컬에 저장한다. 모델·MCP로 보내는 자료의 범위와 비용을 실행 전에 표시한다.
- 초안 생성은 호스트 구독으로 수행하므로 PostGen 화면에서 요청 전 금액을 계산하지 않는다. 사용량은 호스트 호출이 끝난 뒤 제공된 값을 사용한다.
- 텍스트 생성이 끝나면 호출별 실제 사용량을 `ModelUsage`로 정규화해 응답에 담고 해당 작업에 영속 저장한다. 각 항목은 호출 ID, 시각, 단계(`plan-and-draft`/`shared-plan`/`draft`/`evaluation`), 실행 경로, 입력·캐시 입력·출력 토큰, 구독 한도 사용률을 가진다. 다시 생성해도 이전 호출 기록을 보존하고 글별·묶음별 합계를 조회한다. 캐시 입력은 입력 토큰의 부분집합이며 총합에 다시 더하지 않는다. 구독 한도 사용률은 Claude Code CLI의 `stream-json` 출력에 있는 `rate_limit_event`의 5시간·7일 창 `utilization`을 백분율로 바꿔 쓰며, 여러 호출 중 마지막 값을 작업의 최신 상태로 본다. Codex CLI의 `exec --json` 출력은 한도 정보를 주지 않으므로 토큰만 표시하고 한도는 `확인 불가`로 표시한다. 세션 기록 파일 같은 비공식 경로는 읽지 않는다. 사용량을 받지 못한 호출은 `확인 불가`로 두고 0으로 합산하지 않는다. 완료 전에 중단돼 사용량을 받지 못한 호출도 합계가 완전하지 않다고 표시한다. 사용량은 진단 정보이며 게시 페이로드에 넣지 않는다.
- 기본 초안 생성은 독립 글당 호스트 호출 1회이며, 같은 자료를 여러 계정에서 공유할 때만 공통 기획 호출 1회를 묶음에 추가한다. 별도 모델 평가는 사용자 요청 또는 품질 기준선 측정에만 실행한다. 응답 스키마, 출처 ID, 본문·소제목 관계와 지침 세트·해시는 모델 호출 없이 검사한다. 실행 전에 실제 선택 단계와 예상 호출 수를 보여주고, 재생성·재평가를 자동 반복하지 않는다.
- 작업마다 글 모델(`codex`/`claude`)과 이미지 호스트(`manual`/`codex`)를 따로 저장한다. 기존 작업에 이미지 호스트가 없으면 `manual`로 읽는다. Codex 이미지 호출은 승인된 이미지 ID와 자리, 요청서, 원본 참조 경로를 사용한다. 출력 경로는 해당 CLI 실행의 `generated_images/<thread_id>` 안에서만 받고, PNG·JPEG·WebP 파일의 형식·크기(최대 15 MB)를 검사해 로컬 사본을 후보로 저장한다. 설정된 자동 시각 점검은 후보와 원본을 Codex에 보여 준 구조화된 통과 여부·이유이며, 실패 시 최대 생성 횟수까지 재시도한다. 각 생성·점검 호출의 텍스트 토큰과 결과를 이미지 이력에 남긴다. 점검 오류는 통과로 취급하지 않는다. 후보는 최종 발행 선택 전에는 `generatedPath`가 아니다. 최종 발행은 후보를 해당 이미지 ID의 `afterParagraph` 자리에 연결하고, 실패한 자동 점검의 수용도 함께 기록한다. 이미지 자체 사용량과 구독 한도를 받지 못하면 `known: false`와 이유를 반환한다. 금액이나 토큰을 임의로 채우지 않으며 직접 API 가격표를 사용하지 않는다.
- 이미지 제안의 `kind`는 `illustration`·`chart`·`diagram`이다. 이전 초안에 `kind`가 없으면 장면 설명에서 차트·도식 여부를 판별한다. 이미지 요청서는 Assets Manager 표준의 차트·도식 참조 규칙 또는 요청서의 차트·도식 참조를 읽는다. 차트·도식에는 해당 그래프 원본만, 삽화에는 나머지 삽화 원본만 전달한다. 차트·도식 원본이 없으면 조용히 삽화로 대체하지 않고 오류를 낸다.
- 이미지 재생성 요청은 이미지 ID, 화면에 보이는 이전 이미지 경로, 최대 2,000자의 추가 지침을 받는다. 서버는 경로가 현재 후보 또는 연결된 이미지와 일치하는지 확인하고 해당 파일을 생성 호출의 첨부 이미지에 추가한다. 재생성 후보가 연결된 이미지와 공존할 수 있으며 후보 폐기는 기존 이미지를 보존한다. 후보 확정 또는 최종 `발행`은 새 후보로 교체한다.
- 이미지별 `afterParagraph`는 공백을 제외한 본문 줄의 1부터 마지막 줄까지로 검증한다. 초안 상태에서 위치를 바꿀 수 있고 초안 revision을 올린다. 후보 또는 연결된 이미지의 위치 변경은 파일을 버리거나 다시 생성하지 않는다. 발행은 모든 제안 이미지 파일이 존재하고 모든 위치가 유효할 때만 허용한다. 초안의 이미지 호스트 변경은 미검수 후보가 없는 경우에만 허용한다.
- `publishDraftReservation`은 초안의 공개 시각, 주장 충돌 확인, 이미지 파일 존재, 이미지별 배치 위치를 검사한 뒤 후보 이미지를 연결하고 글·공개 시각을 한 번에 승인해 `awaiting_registration`으로 옮긴다. 화면은 공개 시각 입력과 `발행` 버튼을 주요 동작으로 보여주며, 이미지별 확인을 요구하지 않는다. 이 상태 전이는 플랫폼 예약 등록의 시작이지 등록 성공이 아니다. 등록 결과는 플랫폼 영수증을 읽어 따로 확정한다.
- 원본·중간 결과의 보관 기간은 1~3개월이고 기본 3개월이다. 앱 실행 시 및 실행 중 하루 1회 모든 작업의 만료 원본 사본·공통 근거 기획·진단 기록을 활성 작업에서 제거한다. 제거 자료는 작업 ID와 제거·영구 삭제 시각을 기록해 14일 동안 복원할 수 있고, 이후 영구 삭제한다. 복원한 자료는 14일간 재정리하지 않는다. 초안 본문·이미지·URL·평가 및 계정 샘플·자산은 유지한다. 앱이 실행되지 않는 동안 정리는 진행되지 않는다.

## 현재 구현과 남은 검증

`account-registry/v1`은 계정·샘플·자산의 메타데이터, 승인, 대표 샘플을 저장하고 `postgen-next/v1` 작업은 선택 출처 사본, 계정별 초안과 상태 전이를 저장한다. 초안별 편집 잠금과 저장 직렬화, 14일 복원 보관·영구 삭제는 합성 테스트를 통과했으나 장시간·실사용 경합과 실제 데이터 복원은 미검증이다. Codex CLI로 참조 원본을 첨부한 이미지 실생성은 확인했으나, PostGen 화면을 통한 전체 이미지 생성·검수와 실제 사용량 표시는 추가 검증이 필요하다. 승인 당시 샘플 규칙의 불변 스냅샷과 게시 URL 자동 확인도 남아 있다. 구현 상태는 [단계별 범위](02-delivery-scope.md)를 따른다.
