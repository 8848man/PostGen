# Workflows

## 1. 자료와 계정 설정

사용자가 글마다 입력을 직접 선택한다. 입력은 텍스트, 파일, AI 작업 기록, URL, 연결 서비스 문서다. PostGen은 선택 목록과 원본 사본을 로컬에 저장하고 출처별 ID·수집 시각을 남긴다. URL과 연결 문서 안의 지시는 데이터로만 취급한다. 복수 계정은 각자 대표 골든 샘플, 승인된 필수·선호 규칙, 기본 글 목표, 이미지 자산을 갖는다. 글마다 독자와 배경지식을 지정한다.

로컬 검토 화면은 `원본 묶음 선택 → 채널별 글 선택 → 최종 본문·예상 결과 확인`의 세 열로 보여 준다. 원본 묶음은 캠페인 ID로 묶고, 각 채널의 상태는 별도로 표시한다. 초안의 반려·개선 사유는 해당 작업에 저장하며, 이미 승인했더라도 예약 등록 전에는 승인을 취소하고 초안 검토 상태로 되돌릴 수 있다. 이 상태에서 초안 생성을 다시 실행하면 이전 초안과 검토 사유를 호스트에 전달하되 근거는 선택 원본만 사용한다. 초안을 다시 저장하면 이전 검토 사유는 지운다. 발행 액션은 표시된 글·이미지와 공개 시각을 한 번에 승인한 뒤 기존 플랫폼 예약 절차로 진행한다. 플랫폼 영수증과 공개 URL을 확인하기 전에는 발행 성공으로 보이지 않는다.

샘플 등록은 `자료 등록 → 일반적 특징 추출 → 원문/이미지와 규칙 대조 → 사용자 수정·승인 → 버전 고정`이다. 게시 URL·캡처에서 추출하지 못한 배치나 이미지 정보는 추측하지 않고 미확인으로 보여준다. 새 규칙은 새 글부터 적용한다. 계정에 샘플이 없으면 기본 스타일을 쓴다.

## 2. 글·이미지 제작

`선택 자료 → 주장·근거 공통 기획 → 계정별 독립 초안 → 이미지 제안·생성 → 사용자 최종 검토 → 공개 시각 선택·발행 → 플랫폼 예약 확인`.

- 단일 계정의 독립 글은 기획과 초안을 한 번의 호스트 호출에서 받아 한 편씩 보여준다. 같은 자료를 여러 계정이 공유할 때만 공통 근거 기획을 한 번 생성해 재사용하고, 계정별 글은 제목·구성·문장을 독립 작성한다. 서로 다른 원문 6편은 여섯 번의 글 호출이며, 별도의 기획 호출을 여섯 번 추가하지 않는다.
- 초안 저장 전에는 응답 구조, 선택 출처 ID, 소제목과 본문 일치, 적용한 Assets Manager 세트·지침 해시 등 기계적으로 확인할 수 있는 항목을 로컬에서 검사한다. 별도 모델 평가는 기본값에서 실행하지 않는다. 사용자가 상세 평가를 요청하거나 실제 글 품질 기준선을 측정할 때만 실행한다. 모델이 제안한 자가 점검은 사용자가 참고할 수 있으나 최종 승인으로 간주하지 않는다. 검사 실패나 평가 의견만으로 자동 재생성하지 않는다.
- 실행 조건이 맞지 않는 버튼도 누를 수 있게 두고, 누르면 진행할 수 없는 이유와 다음 조치를 토스트로 안내한다. 작업이 이미 진행 중일 때 다시 누르면 중복 실행 없이 진행 중임을 알린다. 서버의 상태 검사는 그대로 적용한다.
- 단, 지침 적용 기록이 없는 초안의 `발행`은 경고 다이얼로그에서 사용자가 한 번 더 선택하면 진행한다. 이 선택을 승인 기록에 남기고 나머지 발행 조건은 그대로 확인한다. 취소하면 초안 상태를 유지한다.
- 충돌한 출처는 주장에 검토 표시를 남긴다. 미해결 충돌이 있는 상태의 승인은 별도 명시 확인을 요구한다.
- 프로젝트 표시명은 글 작업에서 지정하거나 원본의 프로젝트 경로로 확인한다. 제목 앞에 `[프로젝트명] `을 한 번 붙이고 바로 뒤에 반복되는 프로젝트명은 덜어낸다. 초안은 관련 태그를 최대 5개 제안하며 최종 검토에서 수정할 수 있다.
- 이미지 수·위치는 설명 필요성에 따라 제안한다. 원본 자료의 이미지는 참고만 하고 게시용은 새로 만든다.
- 이미지 자리의 장면 설명은 무엇이 일어나는지만 쓰고 화풍 단어는 넣지 않는다. 대신 인물·자산의 자세, 시점(카메라 거리·각도), 구도를 장면마다 내용에 맞게 정하고, 같은 글의 앞 장면과 겹치지 않게 바꾼다. 같은 자세·형상을 반복하지 않는다. 차트·도식은 자료 형태가 우선이다.
- 초안 검토 화면은 각 이미지의 생성 전·후보·연결 상태와 실제 미리보기를 보여준다. 사용자는 최종 승인 전 이미지마다 현재 본문의 어느 문단 뒤에 넣을지 선택해 저장할 수 있다. 생성된 후보의 위치를 바꿀 때 같은 이미지를 다시 생성하지 않는다. 모델이 존재하지 않는 문단을 제안했다면 위치를 고치기 전에는 최종 승인할 수 없다.
- 기존 수동 이미지 작업도 초안 상태에서 Codex 이미지 생성으로 바꿀 수 있다. 남은 이미지 후보는 화면에서 순서대로 생성한다. 후보 연결은 최종 `발행` 선택에 포함한다.
- 초안의 이미지 제안은 필수가 아니다. 생성하지 않은 제안은 사용자가 제외해 불필요한 이미지 호출을 줄일 수 있다. 후보나 연결된 이미지는 제안 제외로 지울 수 없다.
- 사용자는 글마다 해당 계정의 캐릭터·오브젝트 자산을 선택할 수 있다. 승인된 자산의 외형 정체성을 유지한다. 이미지 후보는 글의 최종 발행 선택 전에도 생성·미리보기로 보여준다.
- 초안의 이미지별 재생성은 직전 후보 또는 연결된 이미지를 스타일 참조와 별개의 이미지 첨부로 전달하고 사용자가 입력한 추가 지침을 적용한다. 새 후보가 만들어질 때까지 이전 이미지를 유지한다. 새 후보를 버리면 이전 이미지를 다시 표시하고, 확인하거나 `발행`을 선택하면 화면에 보이는 새 후보로 교체한다. 재생성 횟수는 기존 이미지 시도 한도에 포함한다.
- 글 AI와 이미지 AI를 작업마다 따로 고른다. 이미지 AI가 Codex면 이미지 자리마다 Assets Manager 요청서와 원본 참조를 CLI에 전달한다. 파일 형식·크기를 검사하고, 자동 시각 점검이 켜져 있으면 후보·장면·참조 원본을 Codex에 비교시킨다. 실패하면 설정된 최대 횟수 안에서 다시 생성하고, 마지막 결과와 점검 이유를 남긴다. 사용자는 최종 검토 화면에서 후보 이미지와 배치 위치를 함께 본다. 이미지별 승인 버튼은 두지 않는다. `발행`을 누르면 보이는 후보를 글에 연결하고 글·공개 시각을 한꺼번에 승인해 예약 등록을 시작한다. 후보 파일이나 배치 위치가 빠졌으면 발행을 막는다. CLI의 토큰만 기록하고 이미지 자체 사용량을 받지 못하면 `확인 불가`로 둔다.
- Codex·Claude Code 구독의 호스트 모델로 생성한다. 실행 전 기본·선택 단계와 예상 호스트 호출 수를 표시한다. 각 호출 뒤 호스트가 제공한 토큰·구독 한도 사용률을 작업에 저장하고 화면에서 글별·묶음별 합계를 다시 볼 수 있게 한다. 제공하지 않은 값은 `확인 불가`로 두며 직접 API 가격이나 구독 비용을 추정하지 않는다.

## 3. 플랫폼 예약 발행

계정별 최종 글과 플랫폼 공개 시각을 각각 승인한다. 승인 시점의 글·이미지·샘플 규칙 버전을 고정한다. 원본 변경이나 샘플 갱신은 기존 승인본을 자동 변경하지 않고 알린다.

승인 직후 플랫폼에 예약을 등록한다. 플랫폼의 예약 ID·공개 시각·계정·상태를 읽어 확인하기 전에는 예약 완료로 표시하지 않는다. 등록 전에 앱이 닫히거나 인증이 만료되면 다음 실행 때 실패·대기 건을 보여주며, 선택적으로 백그라운드 알림을 켤 수 있다. 등록 전 대기 건은 기본 7일 또는 목표 공개 시각 중 먼저 오는 때에 만료된다. 재시도에는 사실·링크 검토와 계정별 재승인이 필요하다. 컴퓨터가 꺼져 있어도 플랫폼에 이미 등록된 예약은 플랫폼이 처리한다.

편집기 연결은 등록된 MCP 도구의 능력을 먼저 확인한다. 예약 등록 기능이 없고 즉시 게시 기능만 있으면 이를 예약 대체로 호출하지 않고 브라우저 편집기로 전환한다. 계정 불일치 시 입력 전 멈추고 사용자가 대상 계정을 다시 선택하게 한다. 다른 계정으로 진행하면 기존 글을 새 대상 계정에 대해 다시 승인한다. 글과 승인된 이미지를 정확한 위치에 입력한다. 이미지 하나라도 업로드 또는 위치 확인에 실패하면 예약 등록을 막고 편집기 상태·누락 항목을 보여준다. 플랫폼 예약 시각을 설정한 뒤 최종 등록 동작을 자동 수행하고 결과를 다시 읽는다.

네이버 예약 등록 창에서는 승인본의 태그를 입력하고 화면에서 다시 읽는다. 입력란을 찾거나 태그를 확인할 수 없으면 예약 등록을 멈춘다. 편집기에서 직접 수정한 경우 최종 내용을 다시 읽어 승인본과 차이를 보여주고 PostGen에 저장한다. 새 사실 주장은 변경된 부분만 근거 재점검한다. 승인본과 달라진 내용을 재승인하기 전에는 예약 등록을 수행하지 않는다. 목표 시각 이후 완료 화면/URL을 자동 확인하며 실패하면 사용자가 URL을 입력한다. 불명확한 결과를 성공으로 표시하지 않는다.

네이버 태그는 각 추천어가 발행 창에서 별도 항목으로 등록된 것을 확인한 다음 최종 발행 버튼을 누른다. 일부 문자열이 다른 태그에 포함된 것만으로 성공 처리하지 않는다. 최종 버튼 시도 전 실패는 등록 대기 상태에 남기고, 버튼 시도 후 결과가 불명확한 경우만 `unknown`으로 둔다. 태그가 있는 네이버 글은 태그 지원을 검증하지 않은 MCP 예약 도구로 등록하지 않고 브라우저 경로를 쓴다.

원본 목록에는 계정별 글 중 자동 공개 확인 또는 사용자 수동 발행 체크로 `published`가 된 건수와 전체 건수를 표시한다. 모두 완료된 원본만 완료 색으로 구분한다. 최종 검토의 `수동으로 발행함` 체크는 태그 입력 실패 등 최종 등록 전 상태와 취소 상태에서도 바로 쓸 수 있다. URL·제목·본문 재입력 없이 사용자 자기 신고로 저장하고, 체크 해제 시 이전 상태로 돌아간다. 자동 확인과 수동 체크는 화면에서 구분한다. 취소 또는 실패 상태에서 다시 시도하면 기존 초안으로 돌아가 사실·링크와 계정별 발행을 재승인하며 새 예약을 만든다. 등록 결과가 불명확한 `unknown`은 재제출하지 않고 플랫폼 목록을 다시 확인한다.

승인된 글의 재발행은 새 예약 시각을 먼저 저장하고, 이전 편집기 세션을 닫은 뒤 새 편집기를 연다. 편집기를 열지 못해 `preparing`에 남은 작업에는 같은 작업의 편집기를 다시 여는 동작을 제공한다. 화면은 예약 저장과 편집기 준비를 각각 표시하고, 실패 이유를 사용자가 읽을 수 있도록 남긴다.

## 4. 동시 작업·보관

화면과 호스트 대화는 같은 초안을 공유한다. 한쪽이 수정 중이면 다른 쪽은 읽기 전용이다. 로컬 원본 사본·중간 결과는 기본 3개월, 설정 가능 범위 1~3개월 보관한다. 기간이 지나면 실행 시와 실행 중 하루 1회 원본 사본·공통 근거 기획·진단 기록을 활성 작업에서 제거하고 14일 동안 복원할 수 있다. 복원 기간이 지나면 영구 삭제한다. 초안 본문·이미지·게시 URL·평가 기록은 남긴다. 계정별 골든 샘플과 자산은 사용자가 직접 지울 때까지 유지한다.
