# Verification & Acceptance

## 품질

1. 실제 사용 글의 자동 규칙별 점검과 사용자 평가를 계정·샘플 규칙 버전과 함께 기록한다. 초기 점수를 기준선으로 삼고 버전별 추세를 본다.
2. 필수 규칙 위반은 초안과 함께 구체적 근거를 표시한다. 선호 규칙은 독자·목표 때문에 조정할 수 있고 이유를 남긴다.
3. 출처 충돌은 주장 위치에 표시된다. 미해결 상태의 승인에는 별도 확인 기록이 필요하다.
4. 타인의 공개 샘플에서 고유한 문장·구도·캐릭터 재현을 요구하지 않는다. 외형 고정 자산은 권한 선언을 요구한다.
5. 이미지 제안은 사용자 승인을 거친다. 기본 자동 재생성은 꺼져 있고 설정 시 총 생성 3회를 넘지 않는다.

## 작업·저장

1. 여러 네이버·티스토리 계정의 샘플·자산·목표가 서로 섞이지 않는다. 같은 자료에서도 계정별 글 revision을 따로 만든다.
2. 화면과 호스트에서 같은 초안의 동시 쓰기를 막는다. 승인본은 원본·샘플 변경으로 자동 갱신되지 않는다.
3. 1~3개월 보관 설정과 기본 3개월을 검증한다. 실행 시·하루 1회 정리, 14일 이내 복원, 이후 영구 삭제를 검증한다. 원본/중간 결과 삭제 시 최종 글·이미지·URL·평가와 계정 자산은 유지한다.
4. 요청별 비용 추정과 한도 초과 확인을 검증한다. 호스트 호출 비용은 추정 근거가 없으면 금액을 단정하지 않는다.

## 예약·편집기

1. 승인 직후 플랫폼 예약 등록을 시도한다. 미등록 건은 재실행 때 보여주며 선택적 백그라운드 알림을 보낸다.
2. 미등록 건은 승인 후 7일 또는 목표 공개 시각 중 먼저 오는 때에 만료되고 재시도에는 사실·링크 검토와 재승인이 필요하다.
3. 대상 계정이 다르면 입력 전에 멈춘다. 다른 계정으로 진행하면 그 계정에 대한 재승인을 기록한다.
4. MCP 서버에 예약 등록 기능이 없고 즉시 공개만 있으면 브라우저로 전환한다. 즉시 공개를 예약 대체로 호출하지 않는다.
5. 글과 이미지의 위치·값을 입력 후 다시 읽는다. 이미지 하나라도 실패하면 준비 완료로 기록하지 않는다.
6. 편집 내용이 승인본과 달라지면 재승인 전에는 예약 등록하지 않는다. 플랫폼 예약 ID·계정·시각을 확인하고 목표 시각 뒤 공개 URL을 확인한다. 불명확하면 `unknown`으로 둔다.

## 검증 게이트

합성 자료로 Core 계약·계정 격리·상태 전이를 먼저 시험한다. 호스트·모델·MCP·브라우저 기능은 실제 연결 환경에서 단계별로 검증하고 그 전에는 구현 완료로 표시하지 않는다. 공개 발행 시험은 대상 계정·콘텐츠·공개 범위를 정해 사용자 승인 후 수행한다.
