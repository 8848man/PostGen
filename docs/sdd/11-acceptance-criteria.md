# Acceptance Criteria

MVP 완료 판단은 아래 관찰 가능한 결과를 모두 충족해야 한다. 미검증 항목은 완료로 간주하지 않는다.

| ID | 조건 |
| --- | --- |
| AC-01 | 새 사용자가 현재 작업 폴더에서 Skill을 명시 호출하면 설정·프리셋·입력·주제 선택을 강제받지 않고 제작이 시작된다. |
| AC-02 | 자동 탐색은 현재 폴더에 연결된 Codex·Claude Code 완료 기록만 사용한다. Git 후보는 현재 폴더가 저장소 루트일 때만 포함한다. 다른 폴더에만 등장하는 고유 정보가 초안에 섞이지 않는다. |
| AC-03 | 기록이 없거나 유의미한 근거가 부족하면 원인을 설명하는 빈 상태를 제시하고 사실처럼 꾸민 글을 만들지 않는다. |
| AC-04 | 생성한 Knowledge Package는 Fact, Decision, Evidence, Insight, Example, Asset을 표현하고 모든 확정 Fact와 Decision의 근거를 역추적할 수 있다. |
| AC-05 | 기본 흐름은 하나의 주제를 자동 선정한다. `생성 전에 주제 선택하기`가 켜지면 후보를 보여주고 선택 후 생성한다. |
| AC-06 | 초안은 어려운 용어를 독자 수준에 맞게 풀어 설명하고, 사실·해석·가상 예시를 혼동시키지 않으며 근거와 불확실성을 확인할 수 있다. |
| AC-07 | 사용자의 수정 요청에서 사실 오류·내용·구조·스타일·단발성·지속 선호를 구별한다. 사실 오류는 스타일 제안 횟수에 들어가지 않는다. |
| AC-08 | 같은 스타일 속성 수정이 기본 3회 누적되거나 지속 적용 요청이 있을 때만 비차단형 제안을 한다. 거절·보류의 재표시 규칙이 작동한다. |
| AC-09 | HTML 설정 화면은 필수 항목, 목적 해시태그가 붙은 3개 프리셋, 이미지·HTML·텍스트 레퍼런스 및 추론/직접 지정 속성 구분을 제공한다. 기본 제작에는 나타나지 않는다. |
| AC-10 | 설정 채팅은 Codex와 연결되고 자연어 변경을 검증 가능한 명령으로 변환한다. 허용되지 않은 필드·값·낡은 revision·임의 파일 수정은 거부된다. |
| AC-11 | 초안은 CLI에 먼저 보이고, 파일은 명시적 내보내기 요청에만 생성된다. Markdown/HTML 결과에서 활성 스크립트와 위험한 원문 HTML이 실행되지 않는다. |
| AC-12 | 인증 값과 민감한 대화 본문이 설정 파일·진단 로그·오류 메시지에 저장되지 않는다. 접근 범위 오류와 부분 읽기 실패를 사용자에게 설명한다. |
| AC-13 | 새 매체 Skill이나 입력 제공자를 추가할 때 Knowledge 계약을 변경하지 않아도 된다. 다른 AI의 실행 호스트 지원은 별도 Adapter 작업이다. |
| AC-14 | 후보 목록은 본문 전체를 출력하지 않으며, 명시한 `sourceId`만 기본 문자 예산 내에서 읽는다. 잘림·예산 소진은 진단에 드러난다. |
| AC-15 | Codex·Claude Code 합성 기록과 명시 로그가 공통 출처 형식으로 변환되고 원본 위치가 보존된다. 대화 주장과 Git 변경은 근거 유형으로 구분된다. |

## 파일럿 품질 기준

게시 가능성, 수정 횟수, 사실 오류와 첫 초안 시간은 파일럿에서 기준선을 측정한다. 사전 데이터 없이 합격률 수치를 만들어내지 않는다. 최소한 서로 다른 기록 밀도와 독자 수준을 가진 사례를 사용하고, 평가자가 근거와 해석의 구분을 직접 확인한다.

## 후속 호스트 지원 수용 기준

이 기준은 Codex MVP의 완료 조건과 별개다. Claude Code, Claude Cowork, 기타 호스트마다 실제 설치·명시 호출·근거 있는 초안 생성·수정·명시적 내보내기를 확인해야 지원을 표기한다. 각 호스트에서 같은 Knowledge·Style·BlogDraft 계약과 파일 접근 범위가 유지되어야 한다. Codex 인증·세션 경로가 없는 환경에서도 작동하거나 지원하지 않는 기능을 명확히 표시해야 한다. 자동 기록 탐색이 불가능한 호스트는 제공된 입력으로 작업하는 경로를 검증한다.

## 후속 브라우저 등록 수용 기준

X·Threads·네이버 블로그·티스토리마다 채널 변형의 길이·서식·근거 보존, 실제 편집기 입력값과 미리보기 일치, 계정·공개 범위 확인, 채널별 발행 의사 확인, 게시 결과 URL 또는 완료 화면 검증을 통과해야 지원으로 표기한다. 일부 채널 실패를 성공으로 합치지 않으며, 발행 결과를 확인할 수 없으면 자동 재시도하지 않는다. 세부 상태와 예외는 [Publication Flow Contract](15-publication-flow.md)를 따른다.
