# UX Interaction Contract

## 기본 CLI 흐름

- 호출 즉시 자동 탐색을 시작한다. 초기 설정·온보딩·프리셋·주제 선택은 강제하지 않는다.
- 탐색 범위는 현재 작업 폴더와 연결된 Codex·Claude Code 완료 기록이다. Git 커밋은 보조 근거 후보이며 일반 로그 파일은 사용자가 지정할 때만 읽는다. 현재 호출을 포함한 진행 중 기록은 파일 상태와 내용 경계를 확인해 불완전한 턴을 근거로 쓰지 않는다.
- 주제 후보를 내부적으로 평가하되 기본적으로 최선의 한 주제로 초안을 작성한다. 주제 선택 토글이 켜졌을 때만 후보와 선택 단계를 보여준다.
- 초안 본문에는 독자가 이해할 표현을 우선한다. 출처 표시는 게시용 문장과 구별되고 확인 가능한 원 기록 위치를 가리킨다.
- 저장은 사용자의 내보내기 요청으로만 수행한다. 기본 위치를 제안하되 실제 경로·덮어쓰기·형식은 명시적 의도를 확인한다.

## 수정 의도 분류

| 종류 | 처리 |
| --- | --- |
| 스타일 | 이번 글에 즉시 반영. 같은 속성의 반복 수정 횟수를 정책값으로 집계 |
| 내용 추가·삭제 | 주장과 근거를 재검토하고 이번 글에 반영 |
| 사실 오류 | 근거 재검증, 잘못된 주장 수정·철회. 스타일 집계에서 제외 |
| 구조 변경 | 섹션·순서 재구성. 스타일 불만으로 자동 간주하지 않음 |
| 단발성 편집 | 이번 글만 변경 |
| 지속적 선호 | 적용 범위를 확인한 후 Style Profile에 저장 |

초기 스타일 제안 임계값은 **동일 속성 수정 3회**이며 설정 가능한 정책값이다. 제안은 작업을 막지 않는 UI로 표시한다. 상태는 `accepted`, `rejected`, `deferred`로 기록한다. `accepted`는 명시된 프로필 또는 프로젝트 범위부터 적용하고, 현재 글 포함 여부를 보여준다. `rejected`는 같은 속성·근거의 제안을 반복하지 않는다. `deferred`는 현재 작업에서 재표시하지 않고 새로운 명시 요청이나 충분히 다른 근거가 생길 때만 재평가한다.

## HTML 설정 화면

- 기본 제작에서는 열리지 않는다. Skill 또는 별도 로컬 명령에서 사용자가 요청할 때 연다.
- 항목: 글쓰기 스타일, 어투, 문단 길이/분리 기준, 대상 독자, 설명 난이도, 구성, UI·이미지 스타일, 시각 자료 생성 기준.
- 프리셋 3개는 서로 다른 목적을 해시태그로 설명한다. 예시 방향은 `#쉽게이해`, `#실무기록`, `#깊이있는분석`이며 최종 문구는 사용자 검토 가능한 콘텐츠 데이터다.
- 레퍼런스 분석 결과는 `AI가 추론`, `사용자가 직접 지정`, `미설정`을 구분해 표시한다. 추론값은 사용자가 덮어쓸 수 있다.
- 채팅은 자연어 요청을 스키마 명령으로 변환한다. 검증·적용·변경 내역 표시를 거치며 UI 파일 자체를 AI가 수정하지 않는다.
- Skill Policy는 일반 UI에서 직접 수정하지 않는다. 전문가가 파일 수준에서 수정할 수 있는 구조를 둔다.

## 후속 브라우저 등록 흐름

등록은 사용자가 검토한 초안과 채널을 지정할 때만 시작한다. 기본 초안 생성이나 파일 내보내기 뒤에 자동으로 발행하지 않는다. Postgen은 X·Threads·네이버 블로그·티스토리 각각의 미리보기를 보여주고, 브라우저 편집기에 입력한 뒤 실제 계정·내용·공개 범위를 다시 확인한다. 사용자는 각 채널에서 수정·임시저장·취소·발행을 선택할 수 있다. 채널별 최종 발행 확인과 결과 확인·실패 처리의 단일 원본은 [Publication Flow Contract](15-publication-flow.md)다.
