# Test Strategy

## 검증 원칙

먼저 호스트·기록 형식·설정 채팅의 성립 가능성을 좁은 실험으로 확인한다. 개인정보가 있는 실제 기록은 기본 테스트 픽스처에 복사하지 않는다. 테스트 데이터는 합성 기록을 사용하고, 실제 기록 검증은 사용자 통제 범위에서 최소한으로 수행한다.

## 단계별 테스트

| 단계 | 확인 항목 | 방법·성공 기준 |
| --- | --- | --- |
| 기술 스파이크 | Skill 발견·명시 호출 | 깨끗한 작업 폴더에서 호출하여 예상 Skill이 실행되는지 확인 |
| 기술 스파이크 | Codex 기록 매핑 | 서로 다른 두 폴더의 합성 기록, 잠긴/깨진 파일을 사용해 현재 폴더만 선택하고 오류를 보고하는지 확인 |
| 기술 스파이크 | 혼합 입력·예산 | Codex·Claude Code 합성 기록과 명시 파일을 같은 프로젝트에 두고 출처 분리, 완료 턴, 후보 미리보기, 선택 읽기, 잘림 진단을 확인 |
| 기술 스파이크 | 설정 채팅 | 지원되는 Codex 연결 경로에서 기존 로그인 활용, 구조화 응답, 종료·재연결을 확인. 실패하면 ADR-007 재결정 |
| 계약 | JSON·Profile·명령 | 버전, 타입, 참조 무결성, 직접 지정값 우선, revision 충돌과 알 수 없는 명령 거부 |
| 단위 | 수정 분류와 제안 | 사실 오류를 스타일로 세지 않고, 3회 임계값·거절·보류·범위를 확인 |
| 통합 | 기본 생성 | 선택 단계 없이 자동 탐색→지식→계획→CLI 초안으로 이어지는지 확인 |
| 통합 | 고급 주제 선택 | 토글 on일 때만 후보 선택이 나타나는지 확인 |
| 통합 | 레퍼런스·설정 | 이미지/HTML/텍스트를 추론 후보로 처리하고 사용자의 직접 지정값을 보존하는지 확인 |
| 안전 | 범위·민감정보·HTML | 다른 폴더 혼입, 자료 내 명령, 민감정보 로그, HTML 스크립트, 임의 경로/덮어쓰기 차단 |
| 수용 | 파일럿 글 평가 | 독자가 이해할 수 있는지, 근거를 찾을 수 있는지, 게시 전 수정량을 사람 평가로 기록 |

## 실패 주입 사례

기록 없음, 현재 실행 중 기록, 파일 잠금, 부분 JSONL, 다른 버전 메타데이터, 동일 사실에 대한 상충 기록, 출처 유실, 레퍼런스 내부의 지시문, 매우 긴 기록, 예산 소진, 바이너리 입력, 설정 파일 동시 수정, Codex 인증 만료, 로컬 브리지 미실행을 포함한다.

## 완료 게이트

AC-01~15 중 해당 단계의 기준을 통과하고 알려진 제한을 문서화한다. 기술 스파이크가 실패한 기능은 UI 모형만으로 완료 처리하지 않는다. 선택적 추가 테스트는 남은 구체적 위험을 해결할 때만 수행한다.

## 후속 호스트 적합성 시험

각 새 실행 호스트에서 Skill 발견·호출, 입력 범위 확인, 구조화 생성, 근거 대조, 수정, Markdown/HTML 내보내기를 끝까지 시험한다. 설정 채팅과 로컬 파일 접근은 호스트의 실제 권한·실행 위치에서 따로 검증한다. Claude Code 기록을 Codex에서 읽는 시험은 Claude Code에서 Postgen을 실행하는 시험을 대신하지 않는다. Cowork와 기타 호스트는 지원 기능·제약을 기록하고 후속 호스트 수용 기준을 통과한 경우에만 지원으로 표시한다.

## 후속 브라우저 등록 시험

합성 초안으로 채널별 변환과 중요한 주장·불확실성 표시의 보존을 먼저 시험한다. 브라우저 시험에서는 로그인 만료, 계정 불일치, UI 변경, 편집기 값 불일치, 임시저장, 발행 직후 결과 불명확, 일부 채널 성공을 다룬다. 실제 게시 시험은 대상 계정·콘텐츠·공개 범위를 정해 채널별 발행 승인을 받은 뒤 수행한다. 상세 검증 게이트는 [Publication Flow Contract](15-publication-flow.md)를 따른다.
