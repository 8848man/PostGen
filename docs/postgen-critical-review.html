Product review / Postgen MVP

작동하는 초안 생성기,
검증이 필요한 글쓰기 경험

Postgen의 사용법, 설정 화면, 근거 처리, 글 품질을 저장소의 문서와 구현으로 대조한 비판적 검토입니다. 발견 사항을 우선순위별로 살피고 근거를 직접 열 수 있습니다.

검토 기준: 저장소 문서·소스 및 2026-10-24까지 기록된 검증

종합 판단

기본 호출 경로는 문서화되어 있고 실행도 확인되었습니다. README는 프로젝트 폴더에서 $postgen을 호출하고 CLI에서 초안을 검토하는 순서를 제시합니다. 환경·검증 기록에는 Skill 호출, 기본 생성, 자동 테스트 통과가 남아 있습니다.

첫 설치 방법은 빠져 있고, 설명의 오탈자와 설정 화면의 용어가 첫 사용자의 이해를 방해할 수 있습니다. 출처 참조의 형식을 검사하는 코드와 실제 주장에 맞는 근거를 확인하는 사람의 판단 사이에도 간격이 있습니다.

실제 블로그 글의 게시 가능성·사실 오류율은 평가하지 않았습니다. 이 보고서는 글 품질 점수나 합격률을 만들지 않습니다.

증거를 읽는 방법

구현 확인README·Skill 안내와 실제 소스의 동작 또는 누락을 직접 대조했습니다.
자동·설치 검증 기록환경 문서에 적힌 실행·합성 테스트 결과입니다. 이번 보고서가 그 시험을 재현했다는 뜻은 아닙니다.
미검증·사람 평가 필요실제 기록과 독자를 대상으로 한 글 품질·성능 측정은 아직 없습니다.

발견 사항

각 항목을 열면 영향, 개선 방향, 저장소 근거가 나옵니다. 우선순위는 개선 순서를 위한 판단이며 품질 점수가 아닙니다.

전체 7건 표시
높음

01. 첫 설치부터 호출까지 이어지는 안내가 없다

사용법 · 구현 확인
관찰
README는 Codex CLI에서 $postgen을 부르는 방법을 설명하지만 Skill 설치 명령이나 설치 위치를 단계별로 안내하지 않습니다. 설정 서버 설명도 “설치된 postgen Skill 경로”를 전제합니다. Skill 문서는 호출 후 내부 절차를 자세히 다룹니다.
영향
처음 접한 사용자는 호출 전에 무엇을 설치해야 하는지, 설치가 성공했는지 판단하기 어렵습니다.
개선 방향
지원하는 설치 경로와 확인 절차, 최소 실행 예시를 README 맨 앞에 연결합니다. 설정 화면 실행은 선택 단계임을 같은 흐름에서 설명합니다.
근거
README 사용·설정 안내 · Skill 진입점
높음

02. Knowledge 검증은 근거의 존재와 형식까지만 확인한다

글 품질 · 구현 확인
관찰
validateKnowledge는 Fact·Decision에 출처 참조가 있는지, sourceId가 목록에 있는지, 줄 번호가 양의 정수인지 확인합니다. 해당 줄이 실제 주장과 일치하는지, 출처의 신뢰도가 충분한지, 충돌하는 내용이 해결됐는지는 이 함수에서 검사하지 않습니다.
영향
검증기 통과를 사실 정확성 보증으로 읽으면 잘못된 확신을 줄 수 있습니다. 설치 검증에서 검증기 호출이 확인된 사실과도 구별해야 합니다.
개선 방향
검증 결과를 “구조 검증”으로 표시하고, 중요한 주장에 대해 사람의 출처 대조와 상충 기록 검토를 별도 품질 단계로 둡니다.
근거
Knowledge 검증 코드 · Skill의 근거 지침 · 설치 검증 기록
중간

03. README 오탈자가 첫 실행 안내를 흐린다

사용법 · 구현 확인
관찰
사용법 목록 직후에 단독 숫자 2가 있고, 다음 문장에는 먼저1 텍스트 파일이라고 적혀 있습니다.
영향
별도 단계나 각주처럼 오해할 수 있고, 로그를 파일로 저장해야 하는 조건이 덜 명료해집니다.
개선 방향
두 문자를 정리하고, 일반 CLI 출력과 문서는 명시적 파일 입력이 필요하다는 문장을 예시 명령과 함께 배치합니다.
근거
README 사용 절 · 명시적 입력 절차
중간

04. 설정 화면의 글쓰기 표현이 실제 기능 범위를 흐린다

사용성 · 구현 확인
관찰
화면은 “내 글의 방향을 정해요”, “어떤 글을 쓰고 싶나요?”, “Codex 연결 채팅”이라고 안내합니다. 하단에는 이 화면은 설정만 변경한다고 적혀 있지만, 채팅 입력부 가까이에는 글 생성이 CLI의 Skill에서 진행된다는 설명이 없습니다. 앱 코드는 채팅을 /api/chat으로 보내 Profile을 다시 그립니다.
영향
사용자가 설정 채팅에서 글 자체가 만들어질 것으로 기대하거나 모델 전달 범위를 놓칠 수 있습니다.
개선 방향
입력부를 “글쓰기 설정 요청”으로 명명하고, 옆에 “초안 생성: Codex CLI에서 $postgen”을 배치합니다. 모델 전달 안내도 파일 선택·채팅 위치에 가깝게 둡니다.
근거
설정 화면 문구 · 채팅 처리 코드 · 모델 전달 안내
중간

05. 후보 탐색은 대형 기록에서 비용이 커질 수 있다

수집 성능 · 코드 기반 우려
관찰
36,000자 예산은 선택한 출처를 읽을 때 적용됩니다. 후보 탐색에서는 로컬 JSONL을 재귀적으로 훑고 각 파일을 읽어 파싱하며, 검색어 관련도를 계산할 때 메시지 본문을 합쳐 검사합니다. 후보 목록의 출력은 짧지만 탐색 자체가 본문을 처리합니다.
영향
기록이 많거나 큰 환경에서는 첫 응답 시간이 길어질 가능성이 있습니다. 실제 지연이나 메모리 사용량은 측정되지 않았습니다.
개선 방향
여러 크기의 합성 기록으로 후보 탐색 시간·메모리를 측정하고, 필요하면 메타데이터 인덱스나 단계적 읽기를 검토합니다.
근거
후보 정렬과 읽기 예산 · JSONL 탐색·파싱 · 36,000자 한도와 남은 측정
미검증

06. 실제 블로그 글의 게시 가능성과 사실 오류율

글 품질 · 사람 평가 필요
관찰
문서에는 기본 생성 시 제목과 근거 확인 항목이 나온 사실, 자동 테스트 통과가 기록되어 있습니다. 실제 사용자 기록으로 여러 주제와 독자 수준을 평가한 파일럿은 수행되지 않았습니다.
영향
독자의 이해도, 게시 전 수정량, 사실 오류율을 현재 증거로 판단할 수 없습니다.
개선 방향
서로 다른 기록 밀도와 독자 수준을 가진 초안을 사람 평가자가 읽고, 출처 대조·수정 횟수·첫 초안 시간을 기록합니다. 평가 전에는 수치나 품질 점수를 제시하지 않습니다.
근거
남은 품질 검증 · 파일럿 품질 기준 · 수용 테스트 계획
미검증

07. 혼합 프로젝트와 기록 형식 변화에서의 품질

입력 신뢰성 · 추가 검증 필요
관찰
Codex·Claude Code 합성 세션과 명시 로그의 수집 시험은 기록되어 있습니다. 현재 프로젝트의 실제 후보 3건은 모두 Codex 기록이었고, 실제 혼합 프로젝트에서 글을 만드는 시험은 없습니다. JSONL 형식도 버전마다 달라질 수 있습니다.
영향
실제 혼합 기록에서 주제 선택과 출처 누락이 어느 정도 발생하는지 알 수 없습니다.
개선 방향
버전별·부분 손상·대형 기록 회귀 시험과 실제 혼합 프로젝트 파일럿을 분리해 수행하고, 누락 출처를 사람이 확인합니다.
근거
