# PostGen Next 실행·검증 상태

`npm install` 후 `npm run next`로 로컬 화면을 연다. 서버는 `127.0.0.1`에만 바인딩하고 실행 시 출력된 토큰 URL을 사용한다. 로컬 데이터는 기본적으로 사용자 PostGen 데이터 디렉터리의 `next/`와 계정 레지스트리에 저장한다. 시험용 데이터는 `POSTGEN_DATA_DIR`과 `POSTGEN_NEXT_DIR`로 분리할 수 있다.

첫 화면의 세 열에서 원본 묶음, 채널별 글, 최종 본문·상태를 차례로 선택한다. 채널 글의 `승인`은 해당 초안을 확정하고, `개선`·`반려`는 사유를 기록하며 아직 플랫폼에 등록하지 않은 승인을 철회한다. 이후 `초안 생성`을 다시 누르면 검토 사유와 이전 초안을 반영해 새 초안을 요청한다. `발행 예약`은 승인된 글에서만 보이며 공개 시각과 대상 계정을 다시 확인한 뒤 기존 편집기·예약 등록 절차를 시작한다. `예약 등록됨`은 플랫폼 예약 확인, `발행 확인됨`은 공개 URL 확인을 뜻한다. 계정·자료·제작 설정은 화면 아래의 접이식 영역에 있다.

## 현재 사용할 수 있는 흐름

- 계정·골든 샘플·이미지 자산 등록. 샘플 텍스트/파일/URL/캡처 분석은 Codex CLI를 호출하고, 규칙은 사용자 승인 전에는 기본값으로 쓰지 않는다.
- 직접 텍스트·파일·공개 HTTPS URL·선택한 Codex/Claude 기록·승인된 MCP 문서 도구를 입력 스냅샷으로 만든다.
- Codex·Claude Code 구독의 호스트 모델로 초안을 요청한다. 자동 규칙 평가는 별도 모델 호출이며 실패 시 경고를 기록한다.
- 새 글에서 글 AI(Codex·Claude Code)와 이미지 AI(직접 생성·연결 또는 Codex)를 따로 고른다. 이미지 제안과 계정 자산을 승인한 뒤 Codex 이미지를 생성하면 요청서와 참조 원본을 CLI에 전달한다. 생성 후보는 파일 검사 후 화면에서 미리 보고 확인해야 연결된다. 직접 만든 파일을 검수해 연결하는 경로도 있다.
- 기존 수동 이미지 초안은 화면에서 `Codex 이미지 생성 사용`으로 전환할 수 있다. 불필요한 제안은 생성 전에 제외해 호출 수를 줄인다. 이미지 제안을 승인한 뒤 `남은 이미지 후보 모두 생성`을 누르면 생성되지 않은 이미지들을 순서대로 만든다. 각 후보는 이미지별 카드에 자동으로 표시되며, 사용자가 미리 본 뒤 `이미지 확인·연결`을 눌러야 최종 글에 포함된다. 각 카드의 문단 선택에서 배치 위치를 저장할 수 있고, 위치 변경만으로 이미지를 재생성하지 않는다.
- 계정별 승인, 예약, 7일 만료, 재승인, 로컬 화면에서의 기한 확인. 설정에서 Windows 알림을 켜도 서버를 계속 실행해야 한다. 원본·중간 자료 보관은 1~3개월로 설정한다. 만료 자료는 실행 시·하루 1회 활성 작업에서 제거하며, 14일 동안 복원할 수 있다.
- 설치된 Skill의 `scripts/next-cli.mjs`와 로컬 화면은 같은 작업 저장소를 읽는다. Skill에서 계정별 초안을 만들거나 수정·승인할 수 있다. 화면의 초안 수정 중에는 같은 초안의 CLI 쓰기를 잠그며, 잠금 만료나 revision 충돌 시 새로고침 후 다시 수정한다.
- 계정별 최종본과 공개 시각을 승인하면 플랫폼 예약 등록을 시도한다. 실계정 작업에는 바탕화면의 `포스팅용 크롬.lnk`로 전용 크롬을 열고 `npm run next:chrome`으로 연결한다. `npm run next`의 전용 Edge 프로필 경로는 대체 실행 방식이다. 네이버는 2026-11-15 포스팅용 크롬에서 실제 예약 등록(이미지·소제목 포함)을 확인했다. 네이버 예약 확인은 발행 뒤 화면이 아니라 편집기의 "예약 발행 글" 목록을 별도 탭에서 읽어, 승인한 제목과 서울 시각이 같은 항목이 발행 전보다 정확히 하나 늘었을 때만 등록으로 본다. 티스토리 실제 예약은 아직 검증하지 않았다. 등록 결과가 불명확하면 `unknown`으로 두고 자동 재시도하지 않는다.

### Assets Manager 표준 연결 (글 규칙·이미지 요청서)

사용자의 작업 표준 라이브러리(Assets Manager)를 연결하면, 초안 생성마다 채널의 세트(네이버 기본 `naver-blog-post`)를 라이브러리 명령줄로 받아 쓴다. MCP 서버는 필요 없다.

```powershell
$env:POSTGEN_ASSETS_CLI='D:\projects\assets\app\core\cli.py'   # 없으면 연결하지 않음
# 선택: $env:POSTGEN_ASSETS_SET_NAVER='naver-blog-post'; $env:POSTGEN_ASSETS_PYTHON='python'
npm run next:chrome
```

- PostGen은 `python cli.py standard "<채널> 블로그 포스트: <공통 기획 각도>" --set <세트> --no-gate --json`을 실행한다. 같은 라이브러리 상태면 같은 지침이 나온다. 연결해 두었는데 실패하면 표준 없이 쓰지 않고 생성을 멈춘다.
- 초안: 표준이 기본 규칙이다. 계정 골든 샘플 규칙은 계정별 차이만 더하며, 충돌하면 표준을 따르고 `standard_conflict` 진단을 남긴다. 출력은 PostGen JSON(본문은 기호 없는 문단, 소제목은 `headings`)이고, 표준의 승인 단계·파일 경로·출력 형식 지시는 쓰지 않는다.
- 평가: 표준의 "출력 전 자가 점검" 항목마다 통과 여부와 이유를 `standardChecks`로 받는다.
- 이미지: 초안의 이미지 자리마다 표준의 ImageGen 요청서 형식(자리·장면만 채움)과 참조할 원본 파일 경로를 사용한다. 이미지 AI가 Codex면 이를 CLI에 전달해 생성 후보를 만들고, 사용자가 화면에서 미리 본 후 승인한다. 직접 생성·연결을 고르면 요청서를 클립보드에 복사해 다른 호스트에서 사용할 수 있다.
- 초안에는 어떤 표준으로 썼는지(`draft.standard`: 세트, 지침 sha256, 참조 파일, 요청서 형식)를 남긴다.
- 현재 Assets Manager의 `naver-blog-post` 실제 규칙은 차트·도식에 그래프 원본을 요구하지만 공통 ImageGen 요청서 형식은 삽화 원본을 가리킨다. 차트·도식 요청서 실연동은 이 불일치를 해결한 뒤 다시 검증해야 한다.

### 포스팅용 크롬 연결 (권장, 디버깅 허용을 매번 묻지 않음)

평소 Edge에 붙는 방식(아래)은 연결할 때마다 브라우저가 원격 디버깅 허용을 묻는다. 포스팅 전용 크롬 프로필을 디버깅 포트와 함께 띄우면 이 확인 없이 연결된다.

1. 바탕화면의 **포스팅용 크롬** 바로가기로 크롬을 연다. 바로가기 대상은 다음과 같다.
   ```
   "C:\Program Files\Google\Chrome\Application\chrome.exe" --user-data-dir="D:\chrome-posting" --remote-debugging-port=9333 --remote-debugging-address=127.0.0.1 --no-first-run
   ```
2. 처음 한 번은 그 창에서 네이버 블로그·티스토리에 직접 로그인한다(로그인은 `D:\chrome-posting` 프로필에 남는다).
3. PostGen을 크롬 연결로 실행한다.
   ```powershell
   npm run next:chrome
   ```

`next:chrome`은 `POSTGEN_BROWSER_CDP_ENDPOINT=http://127.0.0.1:9333`을 기본으로 넣고 `next/server.mjs`를 실행한다. 크롬이 닫혀 있으면 준비 단계에서 "Open the posting Chrome shortcut first" 오류가 난다. 포트 9222는 Edge가 쓰는 경우가 많아 9333을 쓴다. 디버깅 포트가 열려 있는 동안에는 이 PC의 다른 프로그램도 그 프로필을 조작할 수 있으므로, 포스팅할 때만 열고 끝나면 닫는다. 평소 쓰는 크롬 프로필에는 크롬 정책상 디버깅 포트가 열리지 않는다.

### 이미 로그인한 Edge 프로필 연결

`npm run next`는 PostGen 전용 Edge 프로필을 연다. 평소 쓰는 Edge 프로필을 사용하려면 실행 중인 Edge의 `edge://inspect`에서 **Remote debugging → Allow remote debugging for this browser instance**를 사용자가 직접 켠다. 이 방식은 연결할 때마다 허용을 물을 수 있어 실계정 작업에는 포스팅용 크롬을 사용한다. PostGen이 브라우저를 종료하거나 로그인 정보를 복사하지는 않는다.

```powershell
$env:POSTGEN_EDGE_CDP_ENDPOINT='msedge'
npm run next
```

`POSTGEN_EDGE_CDP_ENDPOINT`가 지정되면 PostGen은 로컬 Edge에 연결해 **새 탭**에서 해당 계정의 편집기를 연다. 기존 탭을 선택하거나 Edge 전체를 닫지 않는다. 값은 `msedge` 또는 `localhost`·`127.0.0.1`의 HTTP 포트만 허용한다. 편집기의 계정, 제목, 본문, 이미지와 예약 시각 확인은 전용 프로필 경로와 동일하다. 로그인 재사용 여부는 Edge 프로필과 네이버 세션 상태에 달려 있으며, 사이트의 추가 인증을 우회하지 않는다. 실행 중인 Edge에 디버깅 포트를 허용한 경우 `msedge`가 프로필의 `DevToolsActivePort`를 찾아 연결한다. 이 방식은 Edge와 Playwright의 버전에 따라 실제 계정에서 추가 검증이 필요하다.

## 비용·인증

PostGen은 Codex·Claude Code 구독으로 사용하며 직접 API 키를 설정하지 않는다. 실제 사용량은 호출 후 호스트 출력에서 확인한다. 이미지 생성은 호스트 기능에서 수행하므로 PostGen은 별도 가격을 계산하지 않는다.

초안 생성이 끝나면 계획·초안·평가 호출의 실제 토큰 사용량을 화면에 표시한다. Claude Code가 제공한 경우 구독 한도의 5시간·7일 사용률도 함께 표시한다. Codex CLI는 한도 정보를 출력하지 않으므로 `확인 불가`로 표시한다. Windows에서는 npm 설치 위치 또는 데스크톱 Codex 앱의 최신 CLI를 자동 탐색하고, 찾지 못하면 `POSTGEN_CODEX_BIN`에 실행 파일 경로를 지정한다. Codex 이미지 호출의 텍스트 토큰은 기록하지만 이미지 자체 사용량과 구독 한도는 전달받지 못하므로 `확인 불가`다.

## 미완료 검증

2026-11-16에 Assets Manager 원본을 첨부한 Codex CLI 비대화형 이미지 실생성과 PostGen의 결과 파일 수집·형식 검사를 확인했다. `POSTGEN_IMAGE_TEST_REFERENCE`에 원본 이미지 절대 경로를 지정하고 `node tests/host-image-real-smoke.mjs`로 같은 경로를 재검증할 수 있다. 실제 작업 화면에서 생성 후보를 미리 보고 승인하는 전체 흐름과 이미지 자체 사용량 수집은 아직 검증되지 않았다.

Windows npm 설치 위치의 Codex CLI를 자동 탐색해 실제 계획·초안·평가 호출을 통과했다. 격리된 시험 데이터에서 Edge 화면의 초안 생성 버튼으로 초안을 저장하고 토큰 사용량을 표시했다. Claude CLI는 이전 실호출에서 OAuth 세션 만료로 실패했고 재검증은 남아 있다. 이미지 실사용 품질 검증도 남아 있다. Edge의 합성 편집기에서는 계정 확인·필드 입력·문단별 이미지 위치·읽기 확인을 통과했다. 로그인된 네이버·티스토리 화면에서 테스트 이미지가 첫 문단과 둘째 문단 사이에 업로드된 것을 확인하고 편집기 테스트 내용을 지웠다. 포스팅용 크롬에서 네이버 실제 예약 등록과 예약 목록 확인을 2026-11-15에 검증했다. **티스토리 실제 예약과 PostGen의 공개 URL 기록은 미검증**이다. 이 검증 없이는 C를 완료로 표시하지 않는다.

네이버·티스토리 기본 글·예약 필드는 관찰된 화면에 맞춰 연결했다. 두 서비스의 이미지 업로드·문단별 위치를 로그인된 실제 편집기와 합성 편집기에서 확인했다. 실제 로그인된 화면은 컴퓨터 제어로 검증했고 PostGen의 독립 Edge 프로필을 통한 전체 자동 경로는 아직 검증하지 않았다. 일반 편집기 선택자 JSON 경로는 별도 실험용으로 남겨두었다. 네이버는 [스마트에디터 ONE에서 HTML 작성 기능을 지원하지 않는다](https://help.naver.com/service/5593/contents/15545?lang=ko&osType=PC). 티스토리는 [에디터 모드 전환 시 서식 변화가 있을 수 있다](https://notice.tistory.com/2482).
